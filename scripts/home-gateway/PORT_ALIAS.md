# Дополнительный UDP-порт существующего AWG

Если пакеты теряются по пути до внешнего интерфейса VPS, можно отдельно
проверить другой UDP-порт без смены протокола, ключей и профилей других peers.
Сначала сравнить прямой путь и туннель, затем сопоставить счётчики пакетов
на обоих концах. Сам факт потерь не доказывает конкретный механизм фильтрации.

`home-awg-port-alias.service.in` — шаблон для VPS с существующим
`home-awg.service`, iptables и UFW. Он перенаправляет новый входящий IPv4 UDP-порт
на прежний listener. В INPUT после REDIRECT действует разрешение прежнего порта.
Шаблон создаёт новый публичный путь доступа к AWG: перед применением получить
отдельное разрешение владельца на точные адрес, протокол, порт и источник.
В этом шаблоне источник — любой IPv4; для более узкого доступа добавить
одинаковый `-s` в обе команды и согласовать именно его.

1. Проверить WAN-интерфейс, публичный IPv4, старый AWG-порт, свободный новый
   порт, состояние UFW и отсутствие совпадающего правила. Сохранить
   `iptables-save` и исходную конфигурацию peer на самих узлах с правами root.
2. Заменить `@WAN_INTERFACE@`, `@VPS_IPV4@`, `@ALIAS_PORT@` и `@AWG_PORT@`
   проверенными значениями. Готовый unit и параметры конкретной установки
   хранить вне Git. Проверить unit через `systemd-analyze verify`, а правило
   через `iptables-restore --test --noflush` без применения.
3. После разрешения установить unit как `home-awg-port-alias.service`,
   выполнить daemon-reload и start. До успешных проверок не включать автозагрузку.
   Проверить наличие собственного правила через `iptables -C`, отсутствие
   дубликатов — по выводу `iptables -t nat -S PREROUTING`.
4. Сохранив прямой режим домашней сети, изменить только endpoint проверяемого
   peer в его постоянной конфигурации и работающем AWG. Задать новый случайный
   локальный listen-port (`awg set INTERFACE listen-port 0`), чтобы прежняя
   запись conntrack не конфликтовала с REDIRECT. Ключи не выводить в журналы.
5. Проверить потери до peer и внешнего адреса, DNS по UDP/TCP, HTTPS и ожидаемый
   выходной IP. При успехе включить unit для автозагрузки. Уже разрешённый
   автовозврат может вернуть ту же политику после пяти стабильных минут;
   новая ручная проба и confirm требуют обычных отдельных подтверждений.
6. При неудаче восстановить только изменённый endpoint и локальный listen-port,
   остановить и отключить новый unit, проверить удаление его точного правила.
   Удалить только добавленный unit и выполнить daemon-reload. Не очищать
   таблицы iptables целиком и не менять прежний listener.

Перезапуск AWG и перезагрузку VPS проверять отдельно: unit связан с
`home-awg.service` через Requires/After/PartOf и удаляет своё правило при остановке.
Изменение внешнего порта одного peer не обновляет остальные клиентские профили.
