# Домашний AWG: подготовка и аварийное восстановление

Подготовка и включение — отдельные действия. `install_home_ready.sh` не вызывает
`trial`/`rules` и не перезапускает основную службу. Дом остаётся в `direct` до
отдельного разрешения владельца.

## Сетевой путь

Работающий AWG-процесс и его ключ остаются в `home-awg-test`.
`home-awg-uplink.service` добавляет veth `awg-home` / `awg-peer`, узкий NAT и
таблицу 30477. Сокеты sing-box привязаны к `awg-home`; правило `oif` выбирает
AWG-таблицу без явного `routing_mark`, несовместимого с `auto_redirect`.
Метка `0x415747` остаётся отдельным служебным способом доступа к таблице,
но в AWG outbound не устанавливается. Главный default route остаётся физическим.
Метка отличается от служебных меток sing-box `0x2023`–`0x2025`.
Во вспомогательной таблице есть unreachable-маршрут на случай исчезновения
интерфейса, чтобы маркированный трафик не перешёл в direct самопроизвольно.

В режиме правил sing-box выбирает прямой выход либо AWG-интерфейс. Дополнительного
SOCKS-процесса между ними нет. Пакеты не обрабатываются Python: Python нужен
только для управления и проверок. MTU домашнего TUN согласован с AWG: 1280.

## Приоритет правил

1. Локальные адреса — напрямую; IPv6 в текущей IPv4-схеме отклоняется.
2. Устройства в `direct_client_ips` обходят VPN целиком, включая DNS.
3. Пользовательские доменные исключения `vpn_domains` и `direct_domains`.
4. Известные заблокированные домены — через AWG, даже в зоне `.ru`.
5. `.ru`, `.рф` и каталог российских сервисов — напрямую.
6. Остальные направления: пользовательские IP-подсети, заблокированные IP
   через AWG, российские IP напрямую.
7. Всё остальное — через AWG.

Для устройств с полным обходом nftables маркирует пакеты до перехвата TUN.
Их обычный IP-трафик проходит через маршрутизацию и NAT ядра, без обработки
VPN-процессом; DNS обслуживается прямым резолвером. Это подходит для игровых
устройств и рабочего компьютера с корпоративным VPN.

IP-исключения проверяются после доменных правил. Для известного сервиса удобнее
задать доменное исключение. Географическая классификация не абсолютна: один IP
CDN может обслуживать разные сайты. Собственные DoH/ECH приложений могут скрыть
домен; IP-классификация остаётся, но для нужного сервиса лучше явное исключение.

Каталоги российских сервисов/IP — MetaCubeX/meta-rules-dat; заблокированных
доменов/IP — runetfreedom/russia-v2ray-rules-dat. Выбран компактный `ru-blocked`,
а не `ru-blocked-all` на сотни тысяч доменов. `prepare_rule_sets.py` фиксирует
commit источников, SHA256 и размеры, проверяет SRS штатным sing-box и сохраняет
локальные бинарные файлы. В пути пакетов нет скачивания или Python-поиска.
Автоматической установки новых наборов нет: обновить данные, подготовить и
проверить новый кандидат отдельно.

## Установка и проверка

Нужны существующие `home-gateway`, изолированная AWG-проба, `vpn-monitor`,
Python 3.9+, systemd, iproute2, nftables, curl, dnsutils и sing-box 1.14.
Ключи, версии ПО и прошивка на этом этапе не обновляются.

1. Сравнить установленный код с исходниками и сохранить текущие файлы.
2. Установить `awg_uplink.py`, unit и drop-in `awg-uplink-probe.conf` для
   `home-awg-probe.service`; запустить только uplink.
3. Подготовить публичный JSON вне Git с `expected_exit_ip` и
   `direct_client_ips`. Адреса конкретных устройств хранить только локально.
4. От root выполнить `bash install_home_ready.sh SOURCE_DIRECTORY PUBLIC_JSON`.
5. Выполнить `python3 /usr/local/lib/home-gateway/verify_home_ready.py`.

Установщик сохраняет код и настройки в root-only каталоге
`/var/backups/home-gateway/home-ready.*`. SSH/VPN-секреты остаются в своих
приватных каталогах и резервных копиях на устройстве.

Проверка создаёт виртуального клиента `192.0.2.2`, отдельную службу
`home-gateway-lab` и отдельные nft-таблицы. Проверяются AWG-выход, UDP/TCP DNS,
российский IP, обход для игрового устройства, истечение таймера подтверждения,
три сбоя и прямой Интернет/DNS при постоянно падающем процессе.
Тестовые интерфейсы и правила удаляются; основная конфигурация, режим, PID
службы и физический default route должны остаться прежними.

Отдельный тест включает настоящие `auto_route`/`auto_redirect`, помещая весь
тестовый процесс и его интерфейсы в временный network namespace. Виртуальный
клиент использует настоящий перехват, HTTPS и DNS; отдельные veth/NAT пути
моделируют прямой и AWG-выход. Затем намеренно возвращается несовместимый
`routing_mark`, и проверка обязана обнаружить известную runtime-ошибку.
Тестовая служба временно использует `NetworkNamespacePath` через drop-in в
`/run`, который затем удаляется; дополнительные capabilities не выдаются.
Это не заменяет пробное включение на настоящих домашних устройствах.
Одного `sing-box check` недостаточно для проверки runtime-совместимости.

Результат с хешем кандидата сохраняется в `/etc/home-gateway/readiness.json`.
Контроллер откажет во включении, если политика изменилась и хеш не совпадает.
После добавления устройства повторить проверку; она сохраняет исходный режим
дома. Допустимы direct и уже подтверждённый rules; незавершённая домашняя проба
не допускается. Проверяются также автоматический возврат и ручное отключение
на изолированном клиенте. Только его часы стабильности ускоряются в тесте.
Проверяются также хеши исполняемых модулей управления. Для текущей схемы
использовать этот тест и `awg_uplink.py verify`: исторический baseline
`awg_runtime.py verify-baseline` был записан до добавления AWG uplink и больше
не описывает весь допустимый набор служебных маршрутов.

## Откат

`home-gateway-watchdog.timer` на Pi работает независимо от Mac каждые 15 секунд.
По умолчанию он не включает VPN. После явного запуска trial без подтверждения
режим вернётся в direct по таймеру, по умолчанию через 180 секунд.
После подтверждения продолжаются проверки HTTPS-выхода и DNS. Три
последовательных сбоя возвращают direct.

После отдельного разрешения владельца можно включить `gatewayctl auto-return on`
для уже работающего подтверждённого AWG. После аварийного отката этого режима
контроллер проверяет изолированный AWG примерно раз в минуту: HTTPS двух сайтов,
ожидаемый выходной IP и UDP/TCP DNS. Шесть успешных проверок за минимум пять
минут разрешают возврат той же политики. После переключения проверяется основной
процесс; при ошибке восстанавливается direct. Повторная потеря связи вводит паузу
15, затем 30 и максимум 60 минут, после которой заново проверяется стабильность.
После 30 минут стабильного rules накопленная пауза сбрасывается.

Разрешение привязано к конфигурации, хешам исходников и наборов правил.
Их изменение отменяет автовозврат. Ручной `direct`, новая ручная проба,
истечение её таймера и неподтверждённый запуск также отменяют его.
После перезагрузки окно стабильности собирается заново; используются монотонные
часы и идентификатор загрузки. `gatewayctl auto-return off` выключает только
автовозврат. Состояние видно через `status`, `auto-return status` и read-only API.

Если основной процесс не запускается, откат восстанавливает собственный NAT,
убирает оставшийся перехват sing-box и запускает небольшой UDP/TCP DNS-forwarder
к DNS основного роутера. Неисправная VPN-конфигурация не возвращается при ошибке
восстановления. Причина отката видна в API мониторинга и уведомлениях.

Это восстановление работающей Pi. При отказе питания/кабеля вернуть gateway/DNS
DHCP основного роутера на адрес самого роутера и переподключить клиентов.
Название гостевой Wi-Fi-сети само по себе не создаёт независимый обход.

## Команды

Без переключения:

```sh
sudo gatewayctl status
sudo gatewayctl policy
sudo gatewayctl auto-return status
sudo gatewayctl prepare
sudo gatewayctl client direct DEVICE_IP
sudo gatewayctl client remove DEVICE_IP
sudo gatewayctl domain direct example.com
sudo gatewayctl domain vpn example.ru
sudo gatewayctl cidr direct NETWORK_CIDR
```

Исключения сохраняются до следующего явного применения. Предварительно закрепить
DHCP-адрес за MAC. У Wi-Fi и Ethernet одного ПК могут быть разные адреса; для
полного обхода нужны оба используемых подключения. Чужие адреса не угадывать.

Только после отдельного разрешения владельца:

```sh
sudo gatewayctl trial --seconds 180
# После проверки владельцем, до истечения таймера:
sudo gatewayctl confirm
# После отдельного разрешения на будущие автоматические возвраты:
sudo gatewayctl auto-return on
```

Аварийное отключение:

```sh
sudo gatewayctl direct
```

API будущей админки остаётся read-only. Удалённое управление потребует отдельной
авторизации; root-команды через публичный HTTP не открываются.
