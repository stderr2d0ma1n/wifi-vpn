# wifi-vpn

Домашний VPN-шлюз на Linux: AmneziaWG до собственного VPS, выбор прямого или
VPN-маршрута, исключения для устройств и автоматическое восстановление прямого
интернета. Wi-Fi остаётся на основном роутере; Linux-плата подключается к нему
по Ethernet и используется как шлюз и DNS.

В репозитории находятся исходники, systemd units, примеры и инструкции.
Рабочие ключи, VPN-профили, SSH-конфигурация, адреса устройств, база мониторинга
и резервные копии хранятся отдельно и сюда не включаются.

## Как устроено

AmneziaWG работает в отдельном сетевом пространстве. Домашний sing-box выбирает
прямой выход либо AWG-интерфейс. Приоритет имеют исключения для устройств и
доменов, затем списки заблокированных и российских сервисов, затем IP-правила.
Остальное идёт через VPN. Наборы правил компактные, бинарные, с зафиксированными
версиями и хешами; обновления не устанавливаются автоматически.

Устройства с полным прямым обходом используют маршрутизацию ядра, минуя VPN
и пользовательский TUN. Linux-плата при этом остаётся их физическим шлюзом.
Схема IPv4; IPv6 на основном роутере должен быть отключён до отдельной настройки.

Включение выполняется через `gatewayctl trial --seconds 180`. До истечения
таймера нужно проверить устройства и отдельно выполнить `gatewayctl confirm`.
Без подтверждения включается прямой режим. Контроллер на плате продолжает
проверки и после подтверждения: три последовательных сбоя возвращают direct.
Если основной процесс не запускается, предусмотрены маршрутизация ядра и
резервный DNS. Отказ питания самой платы требует ручного обхода через роутер.

По отдельному разрешению `gatewayctl auto-return on` включает возврат той же
подтверждённой AWG-политики после минимум пяти минут стабильных проверок.
Повторные сбои увеличивают паузу до часа. Ручной `direct` отменяет автовозврат;
новая политика требует нового подтверждения. Состояние доступно через
`gatewayctl auto-return status` и API мониторинга.

Явный `routing_mark` в AWG outbound несовместим с `auto_redirect`: рабочая
конфигурация выбирает AWG-таблицу по привязке к интерфейсу. Регрессионная
проверка воспроизводит этот конфликт в изолированном стенде.

## Зависимости и развёртывание

Основные зависимости: Linux, systemd, Python 3.9+, sing-box 1.14, AmneziaWG
userspace/tools, TUN, nftables/NFQUEUE, iproute2, curl и dnsutils. Мониторинг
использует стандартную библиотеку Python. Подробности сборки AWG, VPS и
первоначальной настройки платы описаны в README соответствующих каталогов.

Порядок: подготовить плату и прямой шлюз → VPS и отдельный AWG peer →
изолированную AWG-пробу → модуль мониторинга → домашний uplink и правила →
изолированную проверку → согласованный пробный запуск → подтверждение.
`install_home_ready.sh` предназначен для уже установленного прямого шлюза.
Установщики не следует запускать поверх действующей сети без сравнения
текущих настроек и сохранения резервной копии.

Чат-расписания не требуются для работы шлюза. На плате есть собственные таймеры
аварийного контроллера, мониторинга и проверки релизов. Уведомления потребителя
`client.py` подключаются отдельно. API мониторинга доступен только на loopback,
подходит для будущей личной админки и не предоставляет команд изменения сети.

## Локальная проверка исходников

```sh
python3 -m unittest discover -s scripts/home-gateway -p 'test_*.py'
python3 -m unittest discover -s scripts/vpn-monitor -p 'test_*.py'
python3 scripts/ai_power.py inventory
python3 scripts/ai_power.py check
```

Эти команды не переключают сеть. Интеграционный `verify_home_ready.py` запускается
отдельно на подготовленной Linux-плате в direct или подтверждённом rules. Он проверяет виртуального
клиента, настоящий автоматический перехват в отдельном namespace, DNS, обход
устройства, аварийное восстановление и автовозврат; домашний режим и основной процесс
должны остаться прежними. Успешный стенд не заменяет проверку реальных устройств.

Проверка состава ищет распространённые форматы секретов, машинные пути и
несоответствия инвентарю. Перед отправкой изменений нужно также просмотреть
diff. Приватность репозитория не заменяет отдельное хранение ключей.
