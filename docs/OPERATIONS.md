# Управление и восстановление

Команды выполняются на Linux-шлюзе через заранее настроенный SSH-доступ.
Имена SSH alias, адреса сети и ключи хранятся вне этого репозитория.

## Состояние и исключения

```sh
sudo gatewayctl status
sudo gatewayctl policy
```

Исключение для всего устройства задаётся по закреплённому DHCP-адресу:

```sh
sudo gatewayctl client direct DEVICE_IP
sudo gatewayctl client remove DEVICE_IP
sudo gatewayctl domain direct example.com
sudo gatewayctl domain vpn example.ru
sudo gatewayctl cidr direct NETWORK_CIDR
sudo gatewayctl prepare
```

Изменения политики сохраняются для следующего явного применения. Они не должны
незаметно перезапускать шлюз. После изменения нужен новый изолированный тест.
Для Wi-Fi и Ethernet одного компьютера могут понадобиться разные резервирования
и исключения. Отдельный VPN-клиент на устройстве продолжает применять свои правила.

## Пробный запуск

Только после разрешения владельца:

```sh
sudo gatewayctl trial --seconds 180
```

На телефоне выключить отдельные VPN-клиенты, проверить российский сайт,
нужный зарубежный сервис, видео и приложения. На устройствах-исключениях
проверить корпоративный VPN или игровое соединение. До истечения таймера,
только после отдельного подтверждения владельца:

```sh
sudo gatewayctl confirm
```

Подтверждение снимает ограничение пробного запуска. Аварийный контроллер
продолжает работать. После трёх последовательных сбоев HTTPS/DNS он возвращает
direct; обратно в VPN автоматически не переключается. Если срок пробы уже
истёк, новый запуск согласуется отдельно.

## Прямой выход с работающей платой

```sh
sudo gatewayctl direct
sudo gatewayctl status
```

Ожидается `mode: direct`. Обычно основной сервис активен. При его постоянном
отказе допустим активный резервный DNS (`fallback_dns_active: true`) и обычная
маршрутизация ядра. Проверить открытие сайтов. Если SSH недоступен или плата
обесточена, нужен обход через основной роутер.

## Полный обход платы

1. Открыть локальную панель основного роутера.
2. В DHCP установить шлюз и оба DNS на LAN-адрес самого роутера.
3. Переподключить устройства к Wi-Fi или обновить аренду DHCP.
4. Проверить, что устройства получили роутер как шлюз/DNS и интернет работает.
5. После этого плату можно отключить.

Просто отключить питание платы недостаточно: устройства сохраняют её как шлюз
до изменения DHCP и обновления аренды. Гостевой SSID является независимым
резервом только если действительно выдаёт другой шлюз; название Direct этого
не гарантирует. Сброс роутера к заводским настройкам не требуется.

## Мониторинг

```sh
systemctl list-timers 'home-gateway-*' 'vpn-monitor-*'
curl --noproxy '*' http://127.0.0.1:18765/v1/status
curl --noproxy '*' http://127.0.0.1:18765/v1/updates
```

API только читает состояние. Для удалённой админки использовать SSH-туннель
или собственный авторизованный backend. Не публиковать loopback API напрямую.
Уведомления чата и таймеры на плате — разные механизмы: удаление чат-напоминаний
не отключает локальную защиту и сбор состояния.
